# Changelog

All contract changes must be recorded here.

## v1.1 - checkpoint hardening

### Added

- real parseable synthetic PDF fixtures and deterministic `PDF_INSPECTED` evidence;
- canonical `core.action.action_digest()` binding request ID, tool, arguments, purpose and scenario;
- MCP `tools/approve` release method protected by a one-call bridge proof;
- dashboard MCP client subprocess using JSON-RPC 2.0 over stdio;
- hash-chained standalone approval events;
- replay reporting of final `APPROVED_RELEASE` outcomes;
- canonical `LOG_PATH` and explicit fresh-demo log rotation.

## v1 - foundation

### Added

- `core.schemas.ToolRequest`, `DecisionSignals`, `Decision`, `LayerResult`, `LogEvent`
- `core.canonical` genesis and SHA-256 entry-hash helpers
- `core.append_log.LogWriter` with cross-process locking, redaction and fsync
- `core.verify` CLI with precise tamper reporting
- `core.replay` CLI with deterministic decision digest
- `core.policies` versioned v1 policy matrix
- `core.layers` seven-layer evidence builder
- `tests/test_log.py`, `test_policy.py`, `test_replay.py`, `test_cli.py`, `test_contracts.py`
- `data/fixtures/original_log.jsonl` and `expected_decisions.json`
- `docs/contracts.md`, `docs/architecture.md`, `docs/MEMBER1_IMPLEMENTATION_PLAN.md`
- `docs/demo-evidence/` tamper and replay proof generated by `scripts/demo_member1.py`
- `.github/workflows/ci.yml` test, verify and replay checks

### Contract changes

- Added required `timestamp` to log events.
- Added optional top-level `scenario_id`, `decision`, `evidence_id`, `policy_version`, `analyser_version` to log events.
- Added optional `signals`, `policy_facts`, `layer_results` to decisions.
- Added distinct approval event types: `APPROVAL_SENT`, `APPROVAL_VERIFIED`, `APPROVAL_REJECTED`, `APPROVAL_EXPIRED`.
- Added `SCENARIO_START`, `SCENARIO_END` and `TOOL_TIMEOUT` event types.
- Standardised evidence IDs as deterministic SHA-256-derived identifiers.
- Verification rejects incomplete checkpoint events and duplicate event IDs.
- Replay requires both decision and evidence ID to match.

### Compatibility

- `core.contracts.canonical_json` remains the single canonical representation.
- `ToolRequest` field names match the existing `ai.models.ToolRequest`.
- `DecisionSignals.from_mapping()` accepts the existing `ai.models.AnalysisResult.to_dict()` shape.
